โปรไฟล์งาน ERPสามมิติLocal AIOCRPrivate access

1. เลือกโปรไฟล์ตามงาน ไม่ใช่ตามสิทธิ์

  • Individual: รับบรีฟที่ Intake สร้างโปรเจกต์ บันทึกเวลาที่ Timesheets และติดตามใบแจ้งหนี้
  • SME: เตรียมใบเสนอราคา ติดตามจัดซื้อ ผู้ขาย สินค้าและสต็อกประจำวัน
  • Organization: ตรวจภาระงานข้ามทีม ส่งมอบ ค่าใช้จ่าย และรายงาน

สลับได้โดยไม่ย้ายข้อมูลหรือสร้างองค์กรใหม่ เมนูเพิ่มเติมรวมโมดูลอื่นที่คุณมีสิทธิ์ การเลือก Organization ไม่ทำให้ member กลายเป็น admin และไม่ได้เปลี่ยนสถานะนิติบุคคลของกิจการ

2. เดินงานจากรายการต้นทาง

  1. สร้างลูกค้า/ผู้ขายและข้อมูลกิจการให้ครบก่อนใช้เอกสารจริง ตรวจเลขภาษี ที่อยู่ และสถานะ VAT กับผู้รับผิดชอบ
  2. งานบริการเริ่มที่ Intake หรือ Projects; งานขายเริ่มที่ Quotes และ Clients; งานซื้อใช้ Purchases และรับสินค้าผ่านขั้นตอนที่เกี่ยวข้อง
  3. สินค้าที่ต้องนับสต็อกต้องเป็น Stockable และมีคลัง การปรับยอดต้องระบุเหตุผล ไม่ใช่แก้ตัวเลขเพื่อปิดส่วนต่างโดยไม่มีต้นทาง
  4. ก่อนออกเอกสารการเงิน ตรวจรายการ ยอด หน่วย ภาษี วันที่ และคู่ค้า ใช้ขั้นตอนออก/ยืนยันรายการของระบบเอง ข้อเสนอจาก AI หรือ OCR ยังไม่ใช่รายการที่บันทึกแล้ว
  5. ถ้างวดถูกล็อก ให้ผู้มีอำนาจทบทวนตามกระบวนการปิดงวด อย่าล้างวันที่ล็อกเพื่อข้ามข้อห้าม เอกสารและรายงานดำเนินงานไม่ใช่การยื่นภาษีหรือใบรับรองกฎหมาย

3. ใช้สามมิติให้ตรงคำถาม

  • Organization3D · /warehouse: เห็นยอดภาระงานจาก ERP ตามบทบาท เช่น งานที่ยังไม่เสร็จ ใบเสนอราคา และคำขอค่าใช้จ่าย เลือกโมดูลแล้วไปดูรายการต้นทาง มีมุมมองรายการ ไม่ใช่ภาพจำลองรถยกหรือพนักงาน
  • Network3D · /network: owner/admin ลงทะเบียน native collector บน macOS โดยตั้งใจ แล้วตรวจ snapshot อุปกรณ์ กระบวนการ และปลายทาง established TCP เท่าที่ OS มองเห็น ข้อมูลตัวอย่างแยกจากข้อมูลที่สังเกตจริง
  • Blueprint · /blueprint: สำรวจโครงสร้างโมดูล ERP และกระบวนการด้วยยอดรวม/สถานะ ไม่ใช่ topology เครือข่ายหรือข้อมูลอุปกรณ์

Network3D ไม่อ่านเนื้อหาการสื่อสาร ไม่ครอบคลุม UDP หรือทุก socket ข้อมูลเก่า ขาด หรือถูกตัดคือ unknown ไม่ใช่ safe สัญญาณเป็นรายการให้คนตรวจ ไม่ใช่หลักฐานการรั่วไหลหรือการบล็อกอัตโนมัติ

4. ถามผู้ช่วยที่อ่านข้อมูลตาม session

  1. ตรวจ Local AI ที่ Settings ว่าบริการพร้อมและติดตั้งแชท/ภาพของผู้ช่วย qwen3.5:9b-q4_k_m (GGUF 6,550,825,550 ไบต์) แล้ว การเปิดแอปไม่ดาวน์โหลดเอง ใช้ boombignose pull-model หรือระบุชื่อนี้โดยตรง การติดตั้ง/ลบผ่านเว็บต้องมีทั้ง owner/admin และสิทธิ์ผู้ดูแลเครื่องที่ลงทะเบียนจาก OS
  2. เปิด Assistant แล้วเลือกการอ่านข้อมูล: ERP records ต้องอ่านข้อมูลใหม่ของรอบนั้นตาม workspace/session แม้เป็นคำถามต่อเนื่อง ส่วน Guidance / documents ไม่อ่าน ERP ใช้กับคำแนะนำหรืออ่านไฟล์โดยไม่เทียบรายการ เปลี่ยนขอบเขตจะเริ่มบทสนทนาใหม่ ไม่เปลี่ยนสิทธิ์ของบัญชี
  3. ค่าจริง สถานะ วันที่ และเลขอ้างอิงมาจากผลอ่านของ server; AI เลือกแหล่งและรหัสงานตรวจทาน ไม่เขียนยอดหรืออ้างว่าทำรายการเสร็จเอง ยอดค้างทั้ง workspace แสดงก่อน รายละเอียดอื่นเปิดดูแยกได้ ผล “ไม่พบในผลอ่านนี้” ไม่ใช่การยืนยันว่าไม่มีรายการใน workspace อื่นหรือข้อมูลส่วนที่ยังอ่านไม่ครบ
  4. ตรวจคำแนะนำกับหน้าต้นทางก่อนทำจริง ผู้ช่วยอ่านอย่างเดียว ไม่สร้าง แก้ อนุมัติ จ่าย หรือลบรายการ คำว่า “ควรทำต่อ” ไม่ได้หมายความว่าทำแล้ว

แชทต้องใช้ GGUF เพื่อบังคับ context แบบ portable ไม่ใช้ bare 9B ที่บน Mac อาจเป็น MLX แทน: GGUF ปฏิเสธ prompt 40,018 tokens เมื่อขอ context 32,768 แต่ bare Mac MLX รับไว้ ระบบไม่ตัดข้อความ/context shift หรือสลับโมเดลเงียบ เผื่อ RAM ทั้ง ERP+โมเดล 24 GB+ สำหรับแชท/12 GB สำหรับ OCR เป็นแนวทาง ไม่ใช่ผลวัดขั้นต่ำ ผลจริงจาก Apple Silicon 48 GiB ไม่รับรองข้ามเครื่องหรือคุณภาพ AI ครบชุด ตัวเลขและขอบเขตข้อมูลเป็นของ server ข้อเสนอรอคนตรวจ โมเดลใหญ่ไม่ได้แปลว่าดีกว่า

การอนุมานอยู่ที่บริการโมเดลบนเครื่อง ERP ไม่มี cloud fallback ไฟล์ ข้อความ OCR และข้อความในรายการเป็นข้อมูลที่ต้องระวัง ไม่ใช่คำสั่งที่มีอำนาจเปลี่ยนสิทธิ์ โมเดลยังตอบผิดได้และไม่รับรองกฎหมาย/ภาษี

5. อ่านเอกสารไทย/อังกฤษ แล้วตรวจทุกช่อง

OCR แยกใช้ qwen3.5:4b (3,973,305,013 ไบต์; Apache-2.0 เช่นเดียวกับแชท) ดาวน์โหลดด้วย boombignose pull-model qwen3.5:4b และยังใช้ local MLX ได้ ผล corpus ไทย/อังกฤษ/เลขไทย CER 1.227%/0%/3.004% ยอดและเลขเอกสารสะอาดตรง แต่ JPEG/PDF เอียงคุณภาพต่ำอ่านเดือนผิด จึงต้องตรวจทุกช่อง ไม่ใช่คะแนนความมั่นใจหรือใบรับรอง

  1. เปิด Document OCR ที่ /documents/ocr เลือก JPEG, PNG, WebP หรือ PDF ที่ไม่เข้ารหัส สูงสุด 20 MiB ต่อไฟล์ / 12 หน้า ภาพต้นทางไม่เกิน 20 MP หน้าแอปจะแจ้งข้อจำกัดเมื่อไฟล์ไม่ผ่าน
  2. เทียบภาพต้นฉบับกับข้อความและข้อเสนอของแต่ละหน้า ตรวจผู้ขาย เลขเอกสาร วันที่ รายการ ยอดก่อนภาษี VAT และยอดรวม ช่องว่างคือไม่ทราบ ไม่เติมด้วยการเดา
  3. วันที่กำกวม ยอดผิดรูปแบบ หรือสกุลเงินต่างประเทศอาจไม่มีข้อเสนอ ตัวเลขรวมข้ามหน้าไม่ถูกบวกให้เอง VAT เป็นค่าที่อ่าน ไม่ใช่อัตราที่ระบบรับรอง
  4. หน้า Document OCR ใช้อ่านและตรวจ ไม่สร้างรายการการเงิน เมื่อเรียก OCR จากฟอร์มที่รองรับ ต้องยืนยันว่าเทียบกับต้นฉบับแล้วก่อนกด Use reviewed suggestions in form จากนั้นยังต้องกดเพิ่ม/บันทึก/อนุมัติผ่านขั้นตอนของฟอร์มนั้นแยกต่างหาก

เอกสารถูกประมวลผลในหน่วยความจำ ไม่มีการแนบไฟล์ถาวรหรือบันทึกรายการอัตโนมัติ ถ้าใช้จากโทรศัพท์ผ่าน private access ไบต์เอกสารเดินทางไปยังเซิร์ฟเวอร์ ERP ของคุณ ไม่ได้อนุมานบนโทรศัพท์ ไม่มีคะแนนความแม่นยำที่รับประกัน

6. เข้าแบบ private ยังต้อง login / MFA

ใช้ HTTPS origin ที่ผู้ดูแลกำหนดผ่าน Tailscale Serve แบบ private เท่านั้น สมาชิก tailnet ไม่ได้กลายเป็นสมาชิก ERP โดยอัตโนมัติ เข้าใช้งานด้วยบัญชีและ MFA ตามนโยบายของระบบ คำเชิญและบทบาทยังมีผลเหมือนเดิม

ไม่เปิด Postgres, Auth, REST, API gateway หรือ Ollama ให้โทรศัพท์เชื่อมตรง ไม่ใช้ Funnel/public tunnel และไม่ใส่ secret หรือ enrollment config ลงภาพหน้าจอ ดู ตั้งเซิร์ฟเวอร์ และ บัญชี/สำรองข้อมูลครั้งแรก
