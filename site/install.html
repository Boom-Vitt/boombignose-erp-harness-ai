เปิดเดสก์ท็อปตามระบบ

แฮชไม่ใช่ลายเซ็นผู้พัฒนา macOS ใช้ ad-hoc signing ไม่ใช่ Developer ID/notarization; ไม่มี Authenticode หรือการอนุมัติจาก store ที่หน้านี้รับรอง อย่าปิดนโยบายความปลอดภัยของเครื่องเพื่อข้ามข้อห้าม

Windows เครื่องนี้

  1. เปิด BoomBigNose-windows-x64-setup.exe
  2. ถ้า SmartScreen เตือน ให้ตรวจแหล่งที่มาและแฮชก่อน หากเชื่อถือไฟล์และนโยบายองค์กรอนุญาต จึงใช้ More info → Run anyway
  3. Smart App Control หรือนโยบายองค์กรอาจยังบล็อก ให้ผู้ดูแลทบทวน ไม่รับรองว่า Run anyway จะผ่าน และไม่แนะนำให้ปิดการป้องกัน
  4. ตัวติดตั้งเป็น NSIS ระดับผู้ใช้ โฟลเดอร์เริ่มต้นคือ %LOCALAPPDATA%\BoomBigNose ไม่ได้ขอสิทธิ์ผู้ดูแลระบบ
  5. เปิด BoomBigNose จากเมนู Start หน้าต่างจะสตาร์ท ERP ที่ 127.0.0.1:3100

macOS เครื่องนี้

  1. เปิดไฟล์ .dmg มีเฉพาะ Apple silicon (arm64) ไม่มีไฟล์สำหรับ Intel
  2. คัดลอก BoomBigNose.app ทั้งชุดไป Applications หรือโฟลเดอร์ที่ผู้ใช้มีสิทธิ์ ไม่รันจาก DMG ที่อ่านอย่างเดียว และไม่แก้ไฟล์ใน .app หลังลงชื่อ
  3. แอปลงชื่อแบบ ad-hoc เพื่อความสมบูรณ์ของแพ็กเกจ ไม่ใช่การยืนยันตัวตนนักพัฒนาจาก Apple หรือ notarization
  4. ถ้า Gatekeeper เตือน ให้ตรวจต้นทางและ SHA-256 ก่อน หากนโยบายเครื่องอนุญาต จึงใช้ System Settings → Privacy & Security → Open Anyway
  5. อย่ารันคำสั่งล้าง quarantine ทั้งระบบหรือปิด Gatekeeper เพื่อข้ามนโยบาย

Linux เครื่องนี้

  1. แตก tar.gz แล้วได้โปรแกรมชื่อ BoomBigNose กับโฟลเดอร์ bundle จากนั้นรัน chmod +x BoomBigNose
  2. หรือใช้ AppImage: chmod +x ไฟล์ BoomBigNose-linux-amd64.AppImage แล้วเปิด ถ้าเครื่องไม่มี FUSE ไฟล์นี้อาจเปิดไม่ได้
  3. ต้องมี WebKitGTK 4.1 ในระบบ บน Debian หรือ Ubuntu แพ็กเกจที่พบบ่อยคือ libwebkit2gtk-4.1-0
  4. เปิดแล้วเป็นหน้าต่าง ไม่ใช่คำสั่ง harness

พื้นที่และเครือข่าย

ไฟล์ตัวติดตั้งใหญ่หลายร้อยเมกะไบต์ตามจำนวนไบต์ในการ์ดด้านบน ฐานข้อมูลและโมเดลอยู่คนละที่กับตัวติดตั้ง แชทไม่เรียกโมเดลบนคลาวด์ การกดดึงโมเดลจะติดต่อคลังของ Ollama

Native server · ไม่ต้องมีหน้าต่าง

ซอร์สใหม่มี headless CLI boombignose แยกจาก Go/Wails GUI ใช้ native supervisor เดียวกันโดยไม่ต้องมี WebKit หรือ Docker ขั้นตอนนี้สำหรับผู้ดูแลเครื่อง ไม่ใช่ให้เปิดบริการภายในออกอินเทอร์เน็ต

1. เตรียม release และ data

บน Linux server ใช้ tar.gz ที่ตรวจแฮชแล้ว เก็บ release directory แยกจากข้อมูล ใช้บัญชีบริการที่ไม่ใช่ root ตั้ง BOOMBIGNOSE_BUNDLE และ BOOMBIGNOSE_DATA เป็น absolute path ที่ไม่มีช่องว่าง และพอร์ตไม่ชนของเดิม

บน macOS CLI อยู่ใน BoomBigNose.app/Contents/MacOS/boombignose; บน Windows คือ boombignose.exe ข้าง GUI ไม่ต้องติดตั้ง Node แยก

2. ตรวจและเริ่มเฉพาะ profile

boombignose check
boombignose serve
# Stop only this owned stack:
boombignose stop

คำสั่งใช้ environment ของ profile ที่ตั้งไว้ ค่าเริ่มต้น ERP เป็น loopback 127.0.0.1:3100 อ่าน log แบบ private; health บอก liveness ไม่ได้พิสูจน์ login การเงิน OCR หรือ restore

3. บัญชีก่อน remote

สร้าง owner/workspace ผ่าน local-only onboarding ก่อน สำหรับเครื่องไกลใช้ SSH loopback forwarding แล้วจึงตั้ง exact HTTPS origin ที่ตรวจแล้ว การตั้ง remote origin ปิด open signup ผู้ใช้ถัดไปใช้กระบวนการคำเชิญตามสิทธิ์

systemd/service account, environment, credentials และการกู้คืนฉบับเต็มอยู่ใน คู่มือ native server จากซอร์ส ตรวจคู่มือให้ตรงรุ่นที่ติดตั้ง

Private Tailscale → ERP เท่านั้น

  1. ให้ผู้ดูแลอนุมัติเครื่องและ tailnet ก่อน ตรวจ Serve mapping เดิม อย่า reset หรือทับแอปอื่น ใช้ private HTTPS Serve ไม่ใช้ Funnel/public tunnel
  2. ตั้ง origin ด้วย boombignose configure-public-origin https://YOUR-ERP-HOST.ts.net โดยแทนชื่อด้วย exact HTTPS hostname ของ ERP ที่ได้รับอนุมัติ ไม่มี path/query จากนั้น restart profile ค่านี้อยู่ใน private runtime state ไม่ใช่คำสั่งสร้าง tunnel
  3. ให้ Serve ส่งไป ERP loopback port ของ profile เท่านั้น ห้าม forward API gateway, Auth, REST, Postgres หรือ Ollama ออกเครือข่าย
  4. โทรศัพท์เข้า HTTPS origin ผ่าน tailnet ที่อนุญาต แล้ว login / MFA ของ ERP ตามปกติ Tailscale ไม่แทน session, บทบาท หรือ MFA ของแอป

ไม่มีการเปิด tunnel ลงทะเบียน tailnet หรืออนุมัติอุปกรณ์ให้อัตโนมัติ configure-public-origin off เอานโยบาย origin ออกเมื่อ restart แต่ไม่ยกเลิก Serve mapping ภายนอกให้

Local AI / OCR · ดาวน์โหลดเมื่อสั่ง

โมเดลไม่อยู่ในตัวติดตั้ง

การเปิด GUI หรือ serve ไม่ดึง weights ให้เอง ไป Settings → Local AI หรือติดตั้งแชทด้วย boombignose pull-model / boombignose pull-model qwen3.5:9b-q4_k_m และ OCR ด้วย boombignose pull-model qwen3.5:4b อย่างชัดเจน การติดตั้ง/ลบผ่านเว็บต้องมีทั้ง owner/admin และสิทธิ์ผู้ดูแลเครื่องที่ลงทะเบียนจาก OS

ค่าเริ่มต้นในซอร์สแยกแชท/ภาพของผู้ช่วย qwen3.5:9b-q4_k_m (GGUF 6,550,825,550 ไบต์) กับ OCR ไทย/อังกฤษ qwen3.5:4b (3,973,305,013 ไบต์) ทั้งคู่ Apache-2.0 แชทต้องใช้ GGUF เพื่อบังคับ context ไม่ใช้ bare 9B บน Mac ที่อาจเป็น MLX แทน และไม่ truncate/context shift หรือ fallback เงียบ; OCR แยกยังใช้ local MLX ได้ เผื่อ RAM ทั้ง ERP+โมเดล 24 GB+ สำหรับแชท/12 GB สำหรับ OCR เป็นแนวทาง ไม่ใช่ผลวัดขั้นต่ำ ผลจริงจาก Apple Silicon 48 GiB ไม่รับรองข้ามเครื่อง ยังไม่มีคุณภาพ AI ครบชุดที่ผ่าน และโมเดลใหญ่ไม่ได้แปลว่าดีกว่า

ERP server เป็นเครื่องอนุมาน

บริการ Ollama อยู่บน loopback ของเครื่อง ERP ไม่มี cloud inference fallback; การ pull ติดต่อ registry เพื่อดาวน์โหลดโมเดล เมื่อใช้ผ่านมือถือ เอกสารและคำถามถูกส่งผ่าน private HTTPS ไปเครื่อง ERP ไม่ได้อนุมานบนโทรศัพท์

OCR และผู้ช่วยไม่สร้างหรืออนุมัติรายการการเงินแทนคุณ ตรวจคำตอบ ที่มา วันที่ ยอดและต้นฉบับก่อนบันทึก อ่าน คู่มือเวิร์กโฟลว์

ข้อมูลและอัปเกรดไม่ใช่การ reset

ข้อมูลค่าเริ่มต้นอยู่ที่ ~/.local/share/boombignose/pg หรือ BOOMBIGNOSE_DATA และ credentials/private runtime อยู่ใน <DATA>.secrets คลัสเตอร์ใหม่ใช้ SCRAM แยก credentials ของ admin/Auth/REST ไม่ใช่ trust ตามคู่มือเก่า

ข้อมูลเก่าที่ใช้ trust ต้องหยุดคลัสเตอร์ที่เป็นเจ้าของและทำ cold backup ทั้ง data กับ secrets ก่อนให้เจ้าของเครื่องใช้ boombignose secure-db ไม่รัน initdb ไม่ลบข้อมูล และไม่หยุดบริการคนอื่นเพื่อแย่งพอร์ต ทดลอง recovery ใน profile แยกก่อนย้าย release pointer

สำรองฐานข้อมูลอย่างเดียวไม่รวมไฟล์แนบ/state ทั้งหมด ดู ข้อมูลและการสำรองครั้งแรก และคู่มือ native server สำหรับขั้นตอนกู้คืน ไม่มีผลการ restore หรือการเปิดบนเครื่องของคุณที่หน้านี้รับรอง

ถอนการติดตั้ง

Windows

รัน %LOCALAPPDATA%\BoomBigNose\uninstall.exe สคริปต์ลบโปรแกรม โฟลเดอร์ bundle และทางลัดในเมนู Start ไม่ได้ลบโฟลเดอร์ข้อมูล และไม่ได้ลงรายการใน Apps & features

macOS

ลบโฟลเดอร์ที่คัดลอกออกจากแผ่น หรือ BoomBigNose.app แล้วดีดแผ่นออก โฟลเดอร์ข้อมูลยังอยู่จนกว่าจะลบเอง

Linux

ลบโฟลเดอร์ที่แตกจาก tar.gz หรือลบไฟล์ AppImage โฟลเดอร์ข้อมูลและน้ำหนักโมเดลที่ Ollama เก็บไว้ไม่ถูกลบตามไปด้วย

เมื่อเปิดไม่ได้

คำเตือนจากระบบ

ตรวจต้นทางและ SHA-256 ก่อนเสมอ หากนโยบายอนุญาตจึงใช้ Open Anyway / Run anyway ไม่ปิด Gatekeeper, Smart App Control หรือนโยบายองค์กรเพื่อฝืนเปิดไฟล์

แพ็กเกจ macOS หรือ Linux

macOS ใช้ .app ทั้งชุดและไม่แก้ไฟล์ข้างใน Linux tar.gz ต้องมีไฟล์ executable และ bundle ตรงรุ่น AppImage อาจต้องมี FUSE; headless CLI ไม่ต้องมี WebKit แต่ GUI ต้องมี

พอร์ตหรือ data ไม่ตรง

ใช้ environment ของ profile ที่ต้องการ ตรวจด้วย boombignose check และอ่าน log แบบ private พอร์ตต้องไม่ชน ไม่ใช้ฐานข้อมูลหรือบริการอื่นแทน และไม่ลบ data เพื่อให้สตาร์ทผ่าน

AI / OCR ไม่พร้อม

ตรวจบริการ loopback และโมเดลที่กำหนดใน Settings โมเดลต้องติดตั้งและ runtime ต้องรองรับก่อน การเปิดแอปไม่ pull ให้อัตโนมัติ ถ้าล้มเหลวไม่มีการส่งต่อ cloud; ตรวจ runtime/model configuration ไม่เปลี่ยนไปโฮสต์ภายนอก

คำถาม

มีใน App Store หรือไม่

ไม่มี หน้านี้ให้ดาวน์โหลดไฟล์ตรงเท่านั้น ไม่ได้ส่งแอปเข้า Apple App Store, Google Play หรือ Microsoft Store

ไฟล์ลงชื่อแล้วหรือ

ไม่มีใบรับรองที่ซื้อจาก Apple หรือ Authenticode macOS ที่เป็น .app ลงชื่อแบบ ad-hoc เท่านั้น ตัวติดตั้งรุ่นที่เผยแพร่จึงยังขึ้นคำเตือนของระบบ

หน้านี้รับรองว่าทดสอบเครื่องของฉันแล้วหรือ

ไม่รับรอง คำอธิบายซอร์ส ค่าแฮช CI และ health endpoint ไม่ใช่ผลเปิด GUI ผ่านนโยบาย OS ไม่ใช่ผลตรวจฟีเจอร์ใหม่หรือการ restore บนเครื่องของคุณ อ่านหลักฐานและข้อจำกัดในบันทึกของรุ่นแยกต่างหาก

รุ่นนี้คือรุ่นไหน
