เริ่มใช้อย่างรู้ขอบเขต

เริ่มจากบัญชีและข้อมูลของคุณ แล้วค่อยเปิดโมเดลหรือ private remote access คู่มือนี้ตามซอร์สปัจจุบันที่ยังรอการรวมและตรวจ runtime บันทึก Release เป็นตัวบอกสิ่งที่อยู่ในไฟล์ดาวน์โหลด

บัญชีข้อมูลโมเดลสำรองPrivate access

สร้างพื้นที่ทำงาน แล้วเลือกงานเริ่มต้น

  1. ติดตั้งและตรวจ SHA-256 ตาม หน้าติดตั้ง เปิด BoomBigNose เพื่อเริ่มบริการในเครื่อง หรือให้ผู้ดูแลเริ่ม headless server
  2. ทำ local-only onboarding เพื่อสร้างบัญชี owner และ workspace แรก ไม่ใช้รหัสผ่านเริ่มต้นร่วมกัน ถ้าใช้เซิร์ฟเวอร์ระยะไกล ให้ผู้ดูแลทำขั้นตอนนี้ผ่าน SSH loopback forwarding ก่อนเปิด private HTTPS
  3. เลือก Individual สำหรับงานส่วนตัว/ฟรีแลนซ์, SME สำหรับขาย/ซื้อ/สต็อก หรือ Organization สำหรับข้ามทีม เปลี่ยนโปรไฟล์ภายหลังได้ ข้อมูลและสิทธิ์ไม่เปลี่ยน
  4. เชิญผู้ใช้ตามบทบาทและตั้ง MFA ตามนโยบายบัญชี การอยู่ใน tailnet ไม่ให้สิทธิ์ ERP และไม่ข้ามหน้าล็อกอิน

รู้ว่าอะไรอยู่ที่ไหน

ค่าเริ่มต้นของ native data คือ ~/.local/share/boombignose/pg หรือกำหนด BOOMBIGNOSE_DATA เป็นเส้นทาง absolute ที่ไม่มีช่องว่าง บน Windows ค่าเริ่มต้นอยู่ใต้ %USERPROFILE%\.local\share\boombignose\pg ข้อมูลธุรกิจไม่อยู่ในตัวติดตั้ง

  • ฐานข้อมูล JWT state และไฟล์แนบ private อยู่กับ data profile; บันทึก Postgres คือ server.log ในโฟลเดอร์ข้อมูล
  • credentials ฐานข้อมูลอยู่ใน sibling <DATA>.secrets เช่น pg.secrets/admin.password พร้อม state ของ runtime ไม่ใช่รหัสผ่านล็อกอิน ERP ห้ามส่งไฟล์นี้หรือข้อความในไฟล์ให้ผู้อื่น
  • คลัสเตอร์ใหม่ใช้ SCRAM พร้อม credentials แยกของแต่ละบริการ ข้อมูลเก่าที่ใช้ trust ต้องทำ secure-db โดยเจ้าของเครื่องหลัง cold backup และหยุดคลัสเตอร์ของตนเอง ไม่ reset ฐานข้อมูลเพื่ออัปเกรด
  • ค่าพอร์ตต้องไม่ชนบริการเดิม ถ้าสตาร์ทไม่ได้ให้ตรวจ log แบบ private ไม่ปิด process ที่ไม่เกี่ยวข้อง และไม่เผยแพร่ log/environment ทั้งชุด

เลือกโมเดลเมื่อพร้อมใช้

การเปิดแอปไม่ดึงน้ำหนักโมเดล ไป Settings → Local AI เพื่อตรวจบริการ รายการที่รองรับ ขนาดและสิทธิ์การจัดการ จากนั้นสั่งดาวน์โหลดอย่างชัดเจน ค่าเริ่มต้นในซอร์สแยกเป็น qwen3.5:9b-q4_k_m สำหรับแชท/ภาพของผู้ช่วย (GGUF 6,550,825,550 ไบต์) และ qwen3.5:4b สำหรับ OCR ไทย/อังกฤษ (3,973,305,013 ไบต์) ทั้งคู่ Apache-2.0 ไม่ได้แถมมากับตัวติดตั้ง การติดตั้ง/ลบผ่านเว็บต้องมีทั้งบทบาท owner/admin และสิทธิ์ผู้ดูแลเครื่องที่ลงทะเบียนจาก OS

CLI boombignose pull-model หรือ boombignose pull-model qwen3.5:9b-q4_k_m ดึงแชท; boombignose pull-model qwen3.5:4b ดึง OCR; boombignose models ดูที่ติดตั้ง การดาวน์โหลดใช้ registry/internet แต่ inference อยู่บนเครื่อง ERP ไม่มี cloud หรือ silent model fallback แชทต้องใช้ GGUF เพื่อจำกัด context และไม่ตัดข้อความ/context shift เงียบ ไม่ใช้ bare 9B ที่บน Mac อาจเป็น MLX แทน; OCR แยกยังใช้ local MLX ได้ เผื่อ RAM ทั้ง ERP+โมเดล 24 GB+ สำหรับแชท/12 GB สำหรับ OCR เป็นแนวทาง ไม่ใช่ผลวัดขั้นต่ำ ผลจริงมาจาก Apple Silicon 48 GiB ไม่รับรองเครื่องอื่นหรือคุณภาพ AI ครบชุด ไม่อนุมานว่าโมเดลใหญ่ดีกว่า

เริ่มทดสอบกับข้อมูลสังเคราะห์ ถาม Assistant แบบแคบแล้วตรวจที่มา ลอง OCR บิลตัวอย่างไทย/อังกฤษแล้วเทียบต้นฉบับ คำตอบและยอดที่อ่านได้ต้องผ่านการตรวจของมนุษย์ก่อนใช้จริง ดู คู่มือ AI และ OCR

สำรองก่อนอัปเกรด และทดลองกู้คืนแยก

  1. หยุดเฉพาะแอป/บริการที่เป็นเจ้าของ profile นี้ และยืนยันว่า Postgres ของ profile หยุดแล้ว ก่อนทำ physical cold backup
  2. เก็บทั้ง <DATA> และ <DATA>.secrets พร้อม ownership/permissions, การตั้งค่า และรุ่นแอป/Postgres แบบ private dump ฐานข้อมูลอย่างเดียวไม่รวมไฟล์แนบและ state ทั้งหมด
  3. เข้ารหัสสำเนานอกเครื่องและทดลองกู้คืนลง profile แยก/พอร์ตที่ว่าง ด้วย Postgres major ที่ตรงกัน ห้ามทับข้อมูลเดิมหรือสลับไบนารีเก่าย้อนฐานข้อมูลที่ migrate แล้ว
  4. อ่านขั้นตอน native backup / secure-db / recovery ใน คู่มือผู้ดูแลจากซอร์ส คำสั่งที่มีผลกับข้อมูลต้องให้เจ้าของ profile ตรวจและอนุมัติ

ถอนตัวโปรแกรมไม่ลบข้อมูลหรือโมเดลให้ อย่าลบโฟลเดอร์ข้อมูลเพียงเพราะติดตั้งรุ่นใหม่ บน macOS เก็บ/ย้ายทั้ง .app โดยไม่แก้ภายในแอปที่ลงชื่อแล้ว

Private Tailscale ไม่ใช่ทางลัดผ่าน auth

บริการ ERP และส่วนประกอบภายในใช้ loopback ค่าเริ่มต้น ERP คือ 127.0.0.1:3100 การใช้งานจากโทรศัพท์ต้องตั้ง exact HTTPS origin และ Tailscale Serve แบบ private โดยผู้ดูแลที่ได้รับสิทธิ์ก่อน ไม่มีการเปิด tunnel หรือลงทะเบียนอุปกรณ์ให้อัตโนมัติ

ใช้ tailnet ACL/การอนุมัติอุปกรณ์ และ login/MFA ของ ERP ตามปกติ ไม่เปิด Funnel หรือ forward Postgres/Auth/REST/API/Ollama ตรวจ mapping เดิมก่อนเปลี่ยน ดู ขั้นตอน native server เมื่อใช้งาน OCR/AI จากมือถือ ข้อมูลที่ส่งจะไปประมวลผลบนเซิร์ฟเวอร์ ERP ของคุณ ไม่ใช่บนโทรศัพท์
